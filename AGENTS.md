# AGENTS.md

## Назначение

Это монорепозиторий проекта Lobby. Перед изменением кода прочитай этот файл и `AGENTS.md` в целевом приложении.

## Состав проекта

- `web` — пользовательский интерфейс на React, организованный по FSD.
- `api` — HTTP API проекта на NestJS. Владеет бизнес-операциями, базой данных и записью событий в outbox.
- `mail-service` — изолированный NestJS + Prisma микросервис работы с почтой. Получает сообщения RabbitMQ, фиксирует их в inbox и выполняет почтовые операции.
- `packages/events` — общие типы и контракты событий между приложениями.

Подробные правила: [`.agents/project-architecture.md`](.agents/project-architecture.md), [`.agents/development-workflow.md`](.agents/development-workflow.md), а также локальные инструкции приложений.

## Архитектурные границы

- `web` не обращается к `mail-service`, RabbitMQ или базам данных напрямую.
- `api` не реализует SMTP и не читает inbox `mail-service`.
- `mail-service` не владеет пользовательскими бизнес-правилами и не принимает решения, принадлежащие `api`.
- Межсервисное сообщение должно иметь типизированный контракт в `packages/events`.
- Любое исключение из границ нужно сначала описать в ADR или в соответствующем архитектурном артефакте.

## Обязательные правила для изменений

1. Сначала определи владельца ответственности и затронутый контракт.
2. Не смешивай persistence, orchestration, transport и presentation в одном крупном модуле.
3. Для асинхронных операций проектируй at-least-once delivery: повторная доставка ожидаема, обработка должна быть идемпотентной.
4. Не удаляй и не ослабляй тесты, линтеры и проверки границ без явного обоснования.
5. После изменения запускай проверки целевого workspace и обновляй документацию, если изменились границы или контракт.

## Стиль работы ИИ

- Определяй намерение пользователя по контексту запроса. Если он просит объяснение, диагностику, варианты или инструкции, не изменяй файлы и не запускай изменяющие команды. Редактируй файлы, запускай изменяющие команды или реализовывай решение только когда пользователь явно просит об этом или контекст однозначно подразумевает реализацию.

- **Первый шаг каждого запроса:** активируй `using-agent-skills`, определи применимые skills и следуй их workflow. Это обязательно даже для небольших задач; если подходящего skill нет, зафиксируй это и выбери минимальный безопасный процесс.
- Сначала изучи существующую структуру и локальный `AGENTS.md`.
- Предпочитай небольшие изменения с одной причиной.
- Не создавай новые абстракции без повторяющейся сложности или явной границы ответственности.
- Не делай предположений о контракте события: проверь тип в `packages/events` и потребителей.
- При изменении публичного API или события укажи совместимость, миграцию и влияние на повторную обработку.

## Обязательный skill bootstrap

Для каждого нового запроса ИИ должна:

1. Прочитать `.agents/skills/using-agent-skills/SKILL.md`.
2. Определить фазу задачи и применимые skills.
3. Явно сообщить выбранные skills и причину их выбора.
4. Прочитать выбранные `SKILL.md` до начала изменений.
5. Выполнить verification из выбранных skills и сообщить результат.
