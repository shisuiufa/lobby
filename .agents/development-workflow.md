# Рабочий процесс для ИИ

## Первый шаг каждого запроса

Обязательно начни с `using-agent-skills`: прочитай `.agents/skills/using-agent-skills/SKILL.md`, определи применимые skills, сообщи их пользователю и прочитай их инструкции до начала работы. Это правило действует для вопросов, диагностики, документации, кода и ревью; для простого ответа можно выбрать только этот meta-skill.

## Перед изменением

1. Прочитать корневой и локальный `AGENTS.md`.
2. Найти владельца поведения и существующий модуль, который уже решает похожую задачу.
3. Проверить типы события и публичные интерфейсы.
4. Сформулировать короткий план и затронутые проверки.

## Во время изменения

- Сохранять одну ответственность на модуль, класс, компонент и функцию.
- Делить крупную задачу на вертикальные, проверяемые части.
- Валидацию делать на внешних границах: HTTP, RabbitMQ, env и внешние mail provider responses.
- Для конкурентной обработки использовать уникальные ограничения и атомарные claim/update операции, а не `find` затем `insert/update`.
- Не скрывать ошибки широкими `catch`, не оставлять TODO-стабы и не отключать линтер.

## После изменения

- Запустить форматирование, lint, typecheck/build и релевантные unit/integration/e2e тесты.
- Проверить повторную доставку, retry, отказ внешней зависимости и перезапуск процесса для outbox/inbox изменений.
- Обновить локальный `AGENTS.md`, контракт или ADR при изменении архитектуры.
- В итоговом отчёте указать изменённые файлы и фактически выполненные проверки.
